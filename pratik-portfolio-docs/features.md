# Feature Requirements

## 1. Global shell
- Responsive page container and consistent section spacing.
- Persistent header with name/mark, section links and accessible theme toggle.
- Mobile navigation that opens, closes with Escape, closes after navigation, and exposes correct expanded state.
- Footer with profile/contact links and a restrained closing message.
- Skip-to-content link.

## 2. Identity-first hero
- Clearly display “Pratik Bisen.”
- Use a concise role/positioning statement; content can remain a draft until owner approves it.
- Short introduction that communicates student/developer identity without inflated claims.
- Primary CTA: explore projects.
- Secondary CTA: contact or view resume only if a resume file is provided.
- GitHub and LinkedIn links.
- Real portrait once supplied; clear designed placeholder until then.
- Atmospheric glass / dimensional composition that remains subordinate to content.

## 3. About
- Brief, first-person or third-person introduction (choose one voice and use it consistently).
- Explain current learning focus and what kinds of problems/projects interest the owner.
- Avoid generic claims such as “passionate about technology” without a specific supporting detail.

## 4. Skills
- Organize by category, e.g. programming, web, tools/platforms, and current learning.
- Use only skills supported by owner-provided context or verified project evidence.
- Clearly distinguish practiced skills from learning goals.
- No arbitrary percentage-based proficiency meters.
- Ensure tag lists remain readable and wrap on small screens.

## 5. Projects
- Reusable project card with title, short problem/goal, meaningful description, technology tags, and verified links.
- Include repository and live demo only when they exist and have been checked.
- Project image/screenshot optional; use consistent aspect ratio and descriptive alt text.
- Make the card keyboard accessible without nesting interactive links/buttons incorrectly.
- No invented usage statistics, stars, user counts, or impact claims.
- If a project lacks verification, keep it out of the production display until confirmed.

## 6. Education
- Display B.Tech in Information Technology and SGGSIE&T, Vishnupuri, Nanded.
- Dates and CGPA should only be published after confirming they are current and desired for public display.
- Avoid exposing student ID, phone number, or private records.

## 7. Experience & achievements
- Include confirmed club, coordination, leadership, event, and achievement items only.
- Each item should have role/title, organization, date or period if known, and concise evidence of work.
- Do not label club activity as formal employment.
- If no verified items are ready, hide the section temporarily or use a neutral “Selected community work” framing with approved facts.

## 8. Open-source contributions
- Explain the owner's contribution interests and verified contribution activity.
- Link to GitHub profile and relevant repositories.
- A GitHub API integration is optional and out of scope for initial release unless specifically requested.
- Never display fabricated contribution graphs or hard-coded live-looking activity.

## 9. Contact
- Email CTA uses `mailto:pratikbisen982@gmail.com`.
- GitHub and LinkedIn links.
- External links use clear labels and safe target behavior when opened in a new tab.
- No fake form submission. A real form requires a documented delivery provider and tested success/failure states.

## 10. Theme and motion
- Both dark and light themes.
- Theme toggle is keyboard accessible and communicates current state.
- First-visit theme behavior is consistent and documented.
- Respect reduced-motion preference.
- Animation must not block interaction, cause large layout shifts, or hide content until scripts run.

## 11. Responsive behavior
- Small mobile (320–375 px), typical mobile (390–430 px), tablet, laptop and wide desktop.
- No horizontal overflow.
- Hero layout stacks naturally; portrait and actions remain visible and usable.
- Project cards change column count based on available width.
- Navigation and controls remain touch-friendly.

## 12. SEO and sharing
- Accurate page title and meta description.
- Favicon and Open Graph image once brand assets are ready.
- Semantic headings and crawlable content.
- Canonical URL, sitemap and robots rules only after final domain is known.
- No keyword stuffing or unsupported job-title claims.
