# Persistent Agent Instructions

1. `Context.md` for personal facts, goals, privacy and factual guardrails.
2. `design.md` for visual language and glassmorphism requirements.
3. `features.md` for behavior and scope.
4. `architecture.md` for implementation approach, adapted to the existing repository.
5. `plan.md` for order and acceptance gates.
6. `content.md` for public-facing copy and unverified placeholders.

- Work phase by phase and report outcomes honestly.
- Prefer polished, maintainable code over novelty.

- Implement dark and light themes as complete visual systems.
- Make all sections responsive and keyboard accessible.
- Respect reduced motion.
- Verify every public link and avoid placeholder buttons.
- Keep unconfirmed facts out of the public UI.
- Test both themes at mobile and desktop sizes.
- Use the real portrait only when supplied by Pratik.

## Must not do
- Do not invent personal details, metrics, skills, achievements, work history or project facts.
- Do not create a fake portrait and present it as Pratik.
- Do not claim tests, deployments, or link checks succeeded unless executed.
- Do not add a fake contact form.
- Do not install unnecessary dependencies or introduce paid services without approval.
- Do not use a giant WebGL scene by default.
- Do not overwrite the repository without first inspecting it and explaining risky changes.
- Do not expose credentials or commit secrets.

## Definition of done
The site builds successfully, has no known blocking console errors, has verified links and accurate content, supports both themes and reduced motion, works at narrow mobile widths, and passes the documented acceptance checks. Report remaining owner inputs explicitly.
